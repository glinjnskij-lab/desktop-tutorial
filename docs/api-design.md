# REST API — Conference Booking

## 1. Загальна інформація

REST API призначений для вебсистеми бронювання конференц-залів Conference Booking.

API забезпечує роботу з основними об'єктами системи:

- конференц-зали (Room);
- бронювання (Booking);
- користувачі (User);
- обладнання (Equipment).

Базова адреса API:

`http://localhost:3000/api`

У майбутньому API буде реалізовано на серверній частині вебпроєкту.

---

## 2. Ресурси системи

### 2.1. Rooms

Ресурс `/rooms` використовується для роботи з конференц-залами.

| Метод | Endpoint | Призначення |
|---|---|---|
| GET | `/rooms` | Отримати список залів |
| POST | `/rooms` | Створити новий зал |
| GET | `/rooms/:id` | Отримати інформацію про конкретний зал |
| PUT | `/rooms/:id` | Повністю оновити зал |
| PATCH | `/rooms/:id` | Частково оновити зал |
| DELETE | `/rooms/:id` | Видалити зал |
| GET | `/rooms/:id/equipment` | Отримати обладнання конкретного залу |

---

### 2.2. Bookings

Ресурс `/bookings` використовується для створення та керування бронюваннями.

| Метод | Endpoint | Призначення |
|---|---|---|
| GET | `/bookings` | Отримати список бронювань |
| POST | `/bookings` | Створити бронювання |
| GET | `/bookings/:id` | Отримати конкретне бронювання |
| PUT | `/bookings/:id` | Повністю оновити бронювання |
| PATCH | `/bookings/:id` | Частково оновити бронювання |
| DELETE | `/bookings/:id` | Видалити бронювання |

---

### 2.3. Users

Ресурс `/users` використовується для роботи з користувачами.

| Метод | Endpoint | Призначення |
|---|---|---|
| GET | `/users/:id` | Отримати інформацію про користувача |
| GET | `/users/:id/bookings` | Отримати бронювання користувача |

---

### 2.4. Equipment

Ресурс `/equipment` використовується для роботи з обладнанням.

| Метод | Endpoint | Призначення |
|---|---|---|
| GET | `/equipment` | Отримати список обладнання |
| POST | `/equipment` | Додати обладнання |
| DELETE | `/equipment/:id` | Видалити обладнання |

---

## 3. HTTP-методи

У REST API використовуються стандартні HTTP-методи:

- `GET` — отримання даних;
- `POST` — створення нового ресурсу;
- `PUT` — повне оновлення ресурсу;
- `PATCH` — часткове оновлення ресурсу;
- `DELETE` — видалення ресурсу;
- `OPTIONS` — отримання інформації про доступні HTTP-методи та параметри взаємодії.

---

## 4. HTTP-коди відповіді

API використовує стандартні HTTP-коди:

| Код | Значення | Використання |
|---|---|---|
| 200 | OK | Успішне отримання або оновлення даних |
| 201 | Created | Ресурс успішно створено |
| 204 | No Content | Успішна операція без тіла відповіді |
| 400 | Bad Request | Некоректний запит |
| 401 | Unauthorized | Користувач не авторизований |
| 403 | Forbidden | Доступ заборонено |
| 404 | Not Found | Ресурс не знайдено |
| 409 | Conflict | Конфлікт даних, наприклад подвійне бронювання |
| 500 | Internal Server Error | Помилка сервера |

---
